## Unit 1: Pipeline Multi-Channel Alerter & Sentry Dispatcher
| Field | Content |
|---|---|
| Location | `shorts_engine/services/monitoring/alerter.py:1-131` |
| What it does | Multi-channel failure and quota alert dispatcher supporting Slack, Discord, Telegram, and Sentry. Instantiates webhook targets and Sentry DSN from centralized settings. Formats Markdown payloads, logs alerts locally with matching log level, and captures exceptions into Sentry scopes. |
| Industrial-grade? | **B+** - Functional and clean fallback behavior, but webhooks use blocking synchronous `urllib.request` inside pipeline paths, and Sentry SDK import occurs on every alert call. |
| Checklist | **Error handling:** Pass (catches exceptions around each external notification target independently; failure in one webhook does not abort others). **Timeouts:** Pass (explicit 5s timeout on each `urllib.request.urlopen`). **Retries:** Needs Work (no backoff or retry on webhook transient failures). **Idempotency:** Pass (alerting is naturally idempotent / at-most-once delivery). **Input validation:** Pass (type hints, fallback on empty context dicts). **Resource cleanup:** Needs Work (does not use context manager `with urllib.request.urlopen(...)` causing potential socket leak). **Concurrency safety:** Neutral (stateless instance methods reading immutable settings; however blocking HTTP in async pipeline context can stall event loops or worker threads). **Atomicity:** Pass. **Secret hygiene:** Pass (credentials read from `settings`). **Logging:** Pass (logs locally via Python `logging`). **Telemetry:** Pass (captures tags and extras to Sentry). **Testability:** Pass (can easily mock `urllib.request.urlopen` and `sentry_sdk`). **Cost:** Free/inexpensive (standard webhooks). **Modularity:** Pass (isolated single-purpose class). **Performance:** Needs Improvement (synchronous blocking network I/O; 4 targets with 5s timeouts could stall worker for up to 20 seconds during network partitions). |
| Improvement proposals / Alternatives | 1. **Non-blocking asynchronous or threadpool dispatch**: Dispatch webhook HTTP calls in a background daemon thread or using `asyncio` / connection pooling (`httpx` or `urllib3`) to prevent pipeline worker stalls. 2. **Context manager for socket cleanup**: Wrap `urlopen` calls in `with urllib.request.urlopen(...) as resp:` to ensure sockets are closed immediately. 3. **Module-level Sentry import**: Import `sentry_sdk` once with a try/except guard rather than repeatedly inside `alert()`. |
