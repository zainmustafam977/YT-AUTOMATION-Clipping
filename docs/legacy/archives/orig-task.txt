## 0. Engineering Principles (binding on all work)

1. **Reproduce, then fix.** Every bug is reproduced with captured evidence (logs, exact arguments) and a root cause before code changes. No fixes based on theory.
2. **Verify external facts.** Platform behavior stated in this plan (YouTube API policy, quota, scopes, Win32 behavior) is a claim to confirm against current official documentation. Report any discrepancy in the final report; do not silently adapt.
3. **Fail closed and visible.** Any ambiguity about *which channel* an action targets stops the action and asks the operator. Nothing rebinds credentials or reroutes uploads silently.
4. **One correct mechanism over fallback cascades.** Where a fallback is unavoidable, it is logged and visible to the operator.
5. **Idempotent and recoverable.** Every long-running or external operation survives a crash or restart without duplicating uploads or losing work.
6. **Auditable.** Credential changes, channel bindings, and publish attempts are written to an append-only audit log.
7. **Parity.** Every UI change ships in both the Jinja2 dashboard and the React 19 SPA, unless stated otherwise.
8. **Tests are the definition of done.** Failures are reported honestly. Tests are never weakened to pass.
9. **No secrets in the repo, logs, or screenshots.** Tokens, auth codes, PKCE verifiers, client secrets, and the encryption key are never logged or committed.

## 3. Identity-First Multi-Channel OAuth

### 3.1 Platform facts to confirm against current docs
- One authorization yields one token bound to exactly one channel. For Brand Accounts the operator picks the channel on Google's consent screen; the app cannot preselect it.
- `channels.list(mine=true)` returns only the token's own channel. There is no API that enumerates all channels a Google account manages. Discovery therefore means "each authorization adds one channel."
- `channels.list` is not callable with `youtube.upload` alone. Request both `youtube.upload` and `youtube.readonly`.
- `prompt=select_account consent` forces the account chooser and a fresh refresh token. It does not guarantee a channel chooser. It reduces mistakes; it cannot prevent them. The design detects them.

### 3.2 Core rule
**The channel ID returned by Google (`mine=true`) is the only source of truth for what gets saved.** Every write is an upsert on that ID.

### 3.3 Connect flow
1. Operator clicks **Connect Channel** (new) or **Reconnect** (existing channel). Reconnect sets `intended_channel_id`. For a new connection an optional "Expected handle" field sets `expected_handle`.
2. Backend creates an `oauth_states` row and builds the authorization URL with: opaque state, PKCE (S256), `access_type=offline`, `prompt=select_account consent`, both scopes, redirect `http://127.0.0.1:8000/oauth2callback`. **The state carries no channel data**; intent lives server-side.
3. Callback: look up and consume state (reject unknown, expired, or reused). Exchange the code. If no refresh token is returned, fail the connection with a clear message and offer retry. Never save an unrefreshable credential.
4. Call `channels.list(part=id,snippet, mine=true)` (record 1 unit in the ledger). Extract ID, title, handle, avatar.
5. Reconcile:

| Case | Behavior |
|---|---|
| No intent set | Upsert by channel ID. Show confirmation card: avatar, title, handle, ID, and "Not the channel you wanted? Connect another." |
| Intent matches | Upsert credential, status `active`, set `verified_at`. |
| Intent differs, authorized channel already exists | **Mismatch dialog.** Intended channel untouched. |
| Intent differs, authorized channel is new | **Mismatch dialog.** No auto-import. |

**Mismatch dialog:** "You authorized **B** (avatar, title, handle, ID), but you were connecting **A**." Actions: **Connect B instead** (adds or updates B only), **Retry for A**, **Cancel** (discard token). Every outcome writes an audit entry.

### 3.4 Pre-upload identity guard
Before every upload (including each item in a batch and every retry):
1. Refresh the access token for the job's snapshotted target channel.
2. Call `channels.list(mine=true)` (1 unit, recorded) and compare the ID to `target_youtube_channel_id`.
3. On mismatch, `invalid_grant`, revoked token, or insufficient scope: **do not upload.** Set the credential status, set the job to `PAUSED_NEEDS_ATTENTION` (recoverable, not failed), write an audit entry, and raise a dashboard notification with the cause and a **Reconnect** action. The 1,600-unit upload cost is not incurred; the 1-unit guard call is recorded.
4. After the operator reconnects the correct channel, the paused job resumes without re-entry of metadata.

### 3.5 Token security
- AES-256-GCM at rest, unique nonce per record. Key protected with Windows DPAPI or a key file with restricted ACLs. Key never in the DB or repo.
- **Disconnect** revokes the token at Google, deletes the credential, keeps the channel record and its history.
- Never log tokens, codes, verifiers, or secrets. Add a log-scrubbing test.

### 3.6 Local-app web security
- Bind to `127.0.0.1` only. Validate the `Host` header (defends against DNS rebinding). Require a CSRF token or same-origin check on all state-changing endpoints, including `/api/clips/*/open-folder`.
- Validate every file path against an allow-listed media root.

## 4. Publishing Orchestration, Scheduling, and Quota

### 4.1 Job state machine
`DRAFT → SCHEDULED → UPLOADING → PUBLISHED`, with side states `PAUSED_NEEDS_ATTENTION`, `FAILED`, `CANCELLED`. Transitions are explicit, logged, and persisted before the external call is made.

### 4.2 Reliability requirements
- **Resumable uploads.** Persist `upload_session_uri`. After a crash, resume rather than restart.
- **No duplicate uploads.** Before retrying an upload whose outcome is unknown, check for an existing `youtube_video_id` or resume the stored session. Retry only when it is provably safe, otherwise pause for the operator.
- **Backoff and classification.** Exponential backoff with jitter for transient errors (5xx, network). Treat `quotaExceeded`, `uploadLimitExceeded`, and `forbidden` as non-retryable-now, with a clear cause and next-eligible time.
- **Startup recovery.** On launch, reconcile jobs stuck in `UPLOADING`.
- **Notifications.** Each pause or failure shows cause, affected clip and channel, and the exact next action.

### 4.3 Scheduling mechanism (decision required, default proposed)
Two options; the agent must confirm feasibility against current API policy before building:
- **A. Native scheduling (default):** upload ahead of time with `privacyStatus=private` and `publishAt`; YouTube publishes at the scheduled time even if the PC is off. Quota is spent on the *upload* day.
- **B. Local scheduling:** the app uploads at the scheduled time. Requires the PC and app running at that moment; quota is spent on the publish day.

Make the mode a config setting (`schedule_mode`), show the implications in the UI, and write the choice into the setup guide. If unaudited API projects are forced to private, confirm that scheduled release still works and document the result.

### 4.4 Quota ledger
- The API does not report consumption, so the app keeps a local ledger and labels the gauge **"estimate."**
- Quota is **per Google Cloud project, shared by all channels.** The gauge is global.
- Reset is **midnight `America/Los_Angeles`** (DST-correct), not local time.
- Costs are config constants: upload 1,600, `channels.list` 1. Record every call.
- Operator can **calibrate** "used today" from the Cloud Console.
- **Daily upload cap** = floor((daily_limit − safety_reserve) ÷ upload_cost). With defaults (10,000 limit, 300 reserve) this is **6 uploads/day across all channels combined.** The scheduler and bulk scheduling enforce it and never queue more uploads for a day than the cap.
- Publishing is blocked or warned when the estimate says the limit would be exceeded, with the reset time shown.

## 6. Windows Explorer Fix

1. **Reproduce first.** Log the exact path string and exact command. Check likely causes: forward slashes, `/select,` and the path split into separate list arguments, unquoted paths with spaces or special characters, relative paths. The earlier DDE/privilege-token theory is unverified.
2. **Single endpoint:** `POST /api/clips/{clip_id}/open-folder`. Resolve the absolute path server-side, require it to exist and lie under the media root.
3. **Primary:** normalize to a backslash absolute path and call `explorer /select,"<path>"` as one properly quoted string, or use `SHOpenFolderAndSelectItems` via ctypes with `CoInitialize`. Do **not** treat Explorer's exit code as failure (it returns 1 on success).
4. **One logged fallback:** if the file is missing or the primary raises, `os.startfile(parent_folder)`.
5. **Operator actions, not cascade:** **Copy path** and **Download** (`/api/video/{clip_id}?download=1`) are visible buttons; in-browser playback via `/api/video/{clip_id}`.
6. Return `{ok, method_used, error}` so the toast reports what actually happened.
7. Do not block on the child process; verify no `explorer.exe` accumulation after repeated clicks.
8. **Limitation:** works only when the server runs in the operator's interactive desktop session. Detect and show a clear message otherwise.

## 9. Verification Strategy

### Unit and integration (use a fake YouTube/Google server; no live calls)
- **OAuth:** match; mismatch→new; mismatch→existing (intended channel unchanged); state unknown/expired/reused; no refresh token; unique-constraint enforcement; token log-scrubbing.
- **Guard:** revoked token; token bound to a different channel; missing scope; verify no upload is attempted, job is paused not lost, and ledger records only the 1-unit call.
- **Jobs:** crash during upload resumes; unknown-outcome retry does not duplicate; backoff classification; startup recovery.
- **Quota:** ledger arithmetic; midnight-Pacific reset across a DST boundary; daily cap = 6 with defaults; calibration.
- **Drafts:** optimistic-concurrency conflict (409); flush-before-publish.
- **Validators:** title, description (bytes), tags, forbidden characters, made-for-kids required.
- **Explorer:** normalization and exact argument construction (spaces, `&`, apostrophes, unicode, forward slashes, long paths); path outside media root rejected; fallback only on failure.
- **Security:** Host-header validation; CSRF enforcement; path allow-list.
- **Redirects:** `/publish` and `/app/publish` return 307 to the queue.
- **Migrations:** apply and roll back on a copy of a real database.

Desktop 1440×900: select clip opens docked panel; switch clips; type title; autosave indicator; publish confirmation line shows channel and privacy; mismatch dialog cannot be dismissed into a silent bind; folder action toast is accurate; redirects work.
