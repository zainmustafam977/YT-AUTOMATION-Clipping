# Legacy vault

This folder is a place of last resort for archived legacy material that is no
longer part of the active project but has not been deleted yet.

It is intentionally **not** part of the active project narrative. If an item is
still genuinely useful, it should be migrated into the active documentation or
tooling. If it can safely be removed, prefer deletion over long-term archival
here. Keep this vault small and curated. Retention is only worth preserving when
there is a real reason to keep something — for example legal or compliance needs,
audit evidence, or a known near-term future need.

## Retained subfolders

### `project-handover/`

Archived handover and clarification artifacts. Present: 6 items, primarily legacy handoff notes and clarification/change-request material in a mix of `.md` and `.docx` form. These are retained for context, not as part of the active docs narrative.

### `archives/`

Bulk storage for archived legacy items preserved for reference. Present: 29 items spanning loose legacy files and subfolders with rich internal structure. Names have been normalized to kebab-case.

## How to use this folder

- Treat contents as read-only reference unless a clear retention decision is being
  made.
- Do not point active project docs, onboarding, or runbooks at files inside here
  unless there is no better alternative.
- Before adding anything, ask whether it belongs in the active docs tree instead,
  or should simply be removed.

If this folder starts growing, that is usually a sign that a migration or deletion
decision has been deferred.
