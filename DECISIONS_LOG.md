## 1. Active Technical Standards & Model Selections

| Area | Decision | Details & Implementation | Rationale / History |
|---|---|---|---|
| **LLM Provider** | **Gemini 3.8 Flash** | `LLM_MODEL_NAME = "gemini-3.8-flash"` in `shorts_engine/config/settings.py`. Uses `google-genai` SDK with `CandidateSegmentsResponse` structured output schema. | Gemini 1.5 Flash and 2.0 Flash were officially retired on June 1, 2026. Swappable via `settings.LLM_MODEL_NAME`. |
| **Video Format** | **1080x1920 (9:16 portrait)** | Target resolution 1080x1920. YouTube Shorts duration: 15–58s default (max 180s allowed if extended flag enabled). Single source of truth in `settings.py`. | R2-01 resolved: clip selection and quality gate read from same duration constants. |
| **Safe Margins & UI Collision Boundaries** | **Placement: 420px baseline (Y = 78.1%)<br>Rejection: Y > 80% (bottom 384px)** | • `CAPTION_MARGIN_VERTICAL = 420` in `settings.py` sets ASS subtitle baseline 420px from bottom (`Y = 1500px` on a `1920px` canvas, or `78.1%`).<br>• `UI_DEADZONE_BOTTOM_Y_RATIO = 0.80` in `settings.py` defines the YouTube native title/channel overlay zone (`Y > 1536px`, bottom `384px`).<br>• The 420px placement baseline provides an intentional **36px protective buffer** above the 384px UI dead zone to guarantee multi-line stacks and tall font ascenders never clip into native YouTube overlays.<br>• `render_inspector.py` inspects both the bottom dead zone (`Y > 80%`) and right-side button zone (`X > 85%`) using Canny edge density to reject any render with text bleed. | Arithmetically reconciled across `ass_generator.py` and `render_inspector.py`. Single source of truth in `settings.py`. |
| **Face & Subject Tracking** | **OpenCV YuNet ONNX** | `cv2.FaceDetectorYN` with dynamic model download (`face_detection_yunet_2023mar.onnx`). Haar cascades explicitly dropped. | M-05 resolved: YuNet provides high accuracy across lighting/angle variations without heavy PyTorch model deps. |
| **Audio Loudness** | **EBU R128 normalization** | Compositor applies FFmpeg `loudnorm=I=-14:TP=-1.0:LRA=11`. Target: `-14.0 LUFS`, `-1.0 dBFS` true peak. | Complies with YouTube loudness standards; prevents clipping and distortion across mobile speakers. |
| **Transcription** | **faster-whisper + Forced Alignment** | `faster-whisper` (auto GPU/CPU) with VAD filter + `ForcedAligner` ensuring monotonic timestamps and overlap correction (±50ms bound). | M-03 resolved: eliminates timestamp drift and prevents cutting mid-word or mid-breath. |
| **RSS Polling** | **Python stdlib only** | `xml.etree.ElementTree` + `urllib.request`. Zero external dependencies (no `feedparser`). | Lightweight, robust, eliminates dependency conflicts. |

## 2. Security, Encryption & Key Rotation Standards

| Area | Decision | Details & Implementation | Rationale / History |
|---|---|---|---|
| **Encryption Algorithm** | **AES-256-GCM** | Authenticated AES-256-GCM with PBKDF2-HMAC-SHA256 (600,000 iterations). 16-byte random salt + 12-byte nonce prepended to payload: `[salt][nonce][ciphertext+16-byte auth tag]`. | C-02 & R2-02 resolved: Fernet (fixed to AES-128) explicitly rejected in favor of AES-256. |
| **Single-Value Key Rotation** | `rotate_secret()` | Canonical signature in `shorts_engine/db/security.py`:<br>`rotate_secret(encrypted_b64: str, old_master_key: str, new_master_key: str) -> str` | Decrypts under old key, re-encrypts under new key for an individual value. |
| **Bulk Key Rotation** | `rotate_all_channel_tokens()` | In `shorts_engine/db/security.py`:<br>`rotate_all_channel_tokens(db: Session, old_master_key: str, new_master_key: str) -> int`<br>Wrapped in a **single atomic transaction** with full rollback on any failure. | Delivers full database-wide secret rotation in a single operation. |
| **CLI Rotation Command** | `python run.py rotate-secrets` | CLI command: `python run.py rotate-secrets --old-key <OLD> --new-key <NEW>` | Allows operators to rotate encryption keys during credential rotation runbooks. |
| **Dashboard Transport Security** | **TLS / HTTPS Termination at Ingress** | Uvicorn / FastAPI must NEVER be exposed directly to the public internet on unencrypted HTTP.<br>• Local Dev: Bound to `127.0.0.1:8080` (use TLS tunnels like `cloudflared` or `ngrok` for testing public WebSub callbacks).<br>• Staging & Production: Terminated at ingress / reverse proxy (Caddy, Nginx, or AWS ALB / GCP Cloud Load Balancer) with automated Let's Encrypt certificates, HTTP-to-HTTPS redirect, and HSTS headers. Internal communication to uvicorn is over localhost or private container networks. | Prevents Basic Auth base64 credential sniffing and secures operator review/approve actions over the wire. |
| **Credential & Database Isolation Enforcement** | **Automated Startup Gate & Zero Host Exposure** | • `settings.py` model validator strictly raises `ValueError` if `ENV in ('staging', 'production')` and `DASHBOARD_PASSWORD`, `DASHBOARD_SECRET_KEY`, or `POSTGRES_PASSWORD` equal defaults (`change-me`, `ytpassword_secret_change_me`, `admin`, `password`), or if an insecure password is embedded in `DATABASE_URL`.<br>• `docker-compose.yml` leaves PostgreSQL (5432) and Redis (6379) strictly unmapped from the host network; they communicate solely across internal private container networking (`postgres:5432`, `redis:6379`). | Eliminates database exposure to the public internet and programmatically prevents boot on default database credentials. |
| **Authentication & Access Control** | **Session Cookie Multi-User RBAC & Bearer Tokens (Basic Auth Fully Removed)** | HTTP Basic Auth and shared legacy credentials (`DASHBOARD_USERNAME`/`DASHBOARD_PASSWORD`) have been completely decommissioned and removed from all dashboard routes. All access requires an active `User` record mapped to a role (`admin`, `operator`, `viewer`). Browser sessions authenticate via signed session cookies (`HttpOnly=True`, `SameSite=Lax`) with CSRF protection; non-browser API scripts authenticate via `Authorization: Bearer <session_token>` tied to a real user. No shared credential can bypass the RBAC system. | Resolves M3 access-control integrity: prevents bypass of three-tier RBAC by legacy credentials. |
| **Initial Admin Bootstrap** | `python run.py create-user` | Mandatory first deployment step:<br>`docker compose exec dashboard python run.py create-user --username admin --password <STRONG_PASSWORD> --role admin`<br>Directly seeds the `users` table with PBKDF2-HMAC-SHA256 (600,000 iterations) hash and `UserRole.ADMIN`. Enforces >= 12 char passwords. | Solves first-login bootstrap in a pure RBAC environment without hardcoded credentials. |
| **Secret Masking** | `mask_secret()` | Shows first/last 4 characters, redacts intermediate characters with `...` for safe audit logging. | Prevents secret leakage in error reports and logs. |

## 4. State Machine & Data Model Invariants

| Invariant | Specification | Location |
|---|---|---|
| **Distinct Review States** | `ClipStatus.QUALITY_CHECK` and `ClipStatus.WAITING_APPROVAL` are **distinct enum values**. `QUALITY_CHECK` is an automated processing state; `WAITING_APPROVAL` is the human review queue state. | `shorts_engine/db/models.py` |
| **Unique Constraints** | • `SourceVideo`: `UniqueConstraint("channel_id", "youtube_video_id")`<br>• `PublishLog`: `UniqueConstraint("clip_id", "youtube_video_id")` | `shorts_engine/db/models.py` |
| **Atomic State Locking** | Transitions must go through `LifecycleManager.transition_video()` / `transition_clip()` with optional `expected_status` lock verification. | `shorts_engine/orchestration/lifecycle.py` |
| **Last Seen Video Tracking** | `channel.last_seen_video_id` must be written immediately when a new video is detected in both `RSSPoller` and `PipelineRunner`. | `shorts_engine/services/detection/rss_poller.py`<br>`shorts_engine/orchestration/runner.py` |
| **Dead-Letter Ceiling** | `retry_count` is tracked on `SourceVideo` and `Clip`. If `retry_count >= MAX_RETRY_COUNT` (default 5), retry is blocked and manual intervention is required. | `shorts_engine/db/models.py`<br>`shorts_engine/dashboard/routes/queue.py` |
| **Channel OAuth Credential Storage** | `Channel.encrypted_oauth_token` (`Text`, nullable). Holds the AES-256-GCM encrypted refresh token payload (`[16B salt][12B nonce][ciphertext+16B auth tag]`). Never exposed in plaintext; only decrypted in memory at the moment of upload in `YouTubePublisher`. Bulk rotation orchestrated via `rotate_all_channel_tokens()`. | `shorts_engine/db/models.py`<br>`shorts_engine/db/security.py` |
| **Quota Protection** | `YouTubePublisher` verifies quota before attempting upload. On quota exhaustion, returns `{"quota_exhausted": True}` without mutating status to `FAILED`, preserving clip in `APPROVED` for retry. | `shorts_engine/services/publishing/client.py` |
| **Dialect-Aware Job Locking** | Worker job claiming uses `with_for_update(skip_locked=True)` on PostgreSQL and atomic CAS `UPDATE clips SET rendered_path = ... WHERE rendered_path IS NULL` on SQLite. | `shorts_engine/services/worker/runner.py` |
| **Two-Tier Analytics Scope Isolation** | Tier 1 (Data API v3) provides baseline real-time counts. Tier 2 (YouTube Analytics API) queries retention percentage (`yt-analytics.readonly` scope, 24-48h lag); on scope absence or 403, degrades gracefully to Tier 1 without failing. | `shorts_engine/services/ab_testing/analytics_ingestion.py` |
| **Sole Authentication Gateway** | HTTP Basic Auth and shared passwords are fully decommissioned. All dashboard access strictly resolves to an authenticated `User` record enforcing RBAC permissions. | `shorts_engine/dashboard/auth.py` |
| **Initial Admin Bootstrapping** | In a pure RBAC environment without hardcoded fallback credentials, the first administrator account must be created via CLI: `docker compose exec dashboard python run.py create-user --username <ADMIN> --password <SECRET> --role admin`. Subsequent operators and viewers can then be created via the authenticated UI (`/api/users`) or CLI. | `cli.py`<br>`docker-compose.yml` |

## 6. Client Documentation & Export Fidelity Standard

To prevent text corruption when markdown is converted, exported, or copied across client tools (e.g. Word/PDF/plain text):
1. **Zero LaTeX Math Delimiters (`$`) for Simple Values:** Numerical values, dimensions, screen percentages, and coordinates must NEVER use `$...$` syntax. Always format as clean markdown with backticks (e.g. `80%`, `1080x1920`, `1536px`, `384px`, `Y > 0.80`).
2. **Literal Code and Path Formatting:** File paths, test node IDs, and command strings must be written using standard backticks without escaped backslashes (`tests/test_file.py::test_name`).
3. **Verbatim Test Logs:** Test output must always be written directly to a committed, unedited log file (`test_run_output.txt`) rather than manually summarized or reconstructed in chat messages.
